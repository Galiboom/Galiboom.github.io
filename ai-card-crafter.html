AI-CardCrafter：一次从 0 到上线的全栈 AI 项目复盘

用 React、FastAPI、DeepSeek 和 Vercel 做一个可以真实演示的智能营销卡片生成器。

2026 · 05 · 21 AI 应用 全栈项目 作品集

这篇文章记录我最近完成的一个全栈练手项目：AI-CardCrafter 智能营销卡片生成器。 它面向自媒体运营、跨境电商商家和独立开发者，目标是让非设计人员也能通过一句自然语言，快速生成一张可以编辑、预览和导出的营销卡片。

这个项目不是单纯调用一次 AI，而是把「结构化数据契约、流式生成体验、前端图片导出、线上部署」串成了一条完整链路。

项目要解决什么问题

很多运营内容并不是缺想法，而是卡在视觉表达和文案整理上。比如一句「推荐一款颜值极高的白色防雨运动鞋，适合夜跑」， 如果要变成小红书封面、电商主图或科技风卡片，通常需要懂设计、会排版，还要反复调整文案。

AI-CardCrafter 做的事情是：用户输入原始卖点，AI 生成结构化卡片内容，前端把这些字段映射到不同模板上，并允许用户继续手动微调。 最后，用户可以直接导出高清 PNG，作为真实营销素材使用。

技术栈

React TypeScript Vite Tailwind CSS Zustand FastAPI SQLite SSE DeepSeek API Vercel

前端使用 React + TypeScript + Vite 构建，视觉层采用 Tailwind CSS。状态管理使用 Zustand，把卡片数据、模板 ID、生成状态和导出状态拆开管理。 后端使用 FastAPI，负责封装 OpenAI 兼容格式的 DeepSeek 调用，并通过 SSE 把生成内容逐步推给前端。

核心数据契约

项目的核心是一个统一的 CardPayload。前端组件、后端 Pydantic 校验和 AI 输出都必须遵守同一份结构： 

interface CardPayload {
  title: string
  subtitle?: string
  content: string
  tags: string[]
  themeColor: {
    from: string
    to: string
  }
  emojiIcon: string
}

这样做的好处是边界很清楚：AI 不直接决定页面结构，只负责产出符合契约的数据；前端根据模板 ID 决定布局、字体、渐变色和装饰风格。

最有意思的部分：流式生成

传统 AI 应用往往是等接口返回完整结果后再渲染，体验上会有一段明显空白。这个项目使用 text/event-stream， 后端把字段拆成 patch 事件逐步发送，前端收到后立即注入 Zustand 状态。

最终效果是：标题、副标题、正文和标签会像打字机一样逐步出现在卡片上。AI 写入期间，对应卡片区域还有轻微呼吸灯效果， 用户能明确感知到「内容正在生成」。

前端体验设计

首版提供三套模板：

  • 小红书爆款风：强调情绪、种草感、贴纸式视觉。
  • 科技极客风：强调网格、深色、高可信表达。
  • 电商促销风：强调利益点、转化感和商品主图氛围。

左侧是控制面板，用户可以修改标题、副标题、正文、标签、Emoji 和渐变色；中间是固定比例实时画布。 任何一次表单修改都会即时反馈到卡片上，避免「先编辑、再预览」的割裂感。

导出与草稿

为了让它不仅是一个 Demo，我加入了两个实用能力：本地草稿和高清导出。

  • 草稿使用 localForage 写入 IndexedDB，每隔 2 秒自动保存一次。
  • 导出使用前端 DOM 转图片方案，并提高采样倍率，适配 Retina 高分屏。

这两个功能让它更接近真实工具：刷新页面不会轻易丢内容，生成好的卡片也能马上变成可用图片。

部署过程

项目代码托管在 GitHub，并通过 Vercel 部署。前端作为 Vite 静态站点构建，后端通过 Vercel Python Function 暴露 FastAPI 入口。 线上环境变量中配置 DeepSeek 的 API Key、Base URL 和模型名。

部署过程中也踩了几个坑，比如 Vercel 对根目录 requirements.txt 的解析、无状态文件系统下 SQLite 路径、以及环境变量修改后必须重新 Redeploy。 这些问题最后都被整理进了部署配置里。

我从这个项目里学到了什么

  • AI 应用的重点不只是「接上模型」，还包括数据契约、失败兜底和交互反馈。
  • SSE 很适合做轻量级生成式体验，比一次性等待完整 JSON 更有生命力。
  • 作品集项目最好能闭环到线上地址，而不是只停留在本地截图。
  • 前端导出图片、离线草稿、部署环境变量这些细节，会显著提升项目完整度。

总结

AI-CardCrafter 是一个小而完整的全栈 AI 项目：它有清晰用户场景，有完整前后端链路，也有能在线演示的最终形态。 对我来说，它更像是一次把「产品想法、工程实现、部署发布、作品展示」串起来的练习。

接下来如果继续迭代，我会考虑加入更多模板、历史作品管理、图片素材上传，以及更细粒度的设计参数控制。
