森林法术旅团：从 2D MVP 到 3D 网页生存游戏复盘

一次用 TypeScript、Three.js 和 Vite 构建原创森林法术生存游戏的完整记录。

2026 · 05 · 23 Three.js Browser Game TypeScript

森林法术旅团 是一个浏览器优先的原创 3D 生存游戏 MVP。最初的目标很明确： 做一个能在网页里直接玩的单机小游戏，核心体验是边走位、边自动施法、边通过升级选择构筑自己的法术路线。

这次项目有一个很重要的前提：它可以借鉴“森林山地”“法术构筑”“荒诞鱼群”这些方向，但不直接复刻任何现成 IP 的角色、名字、造型和素材。 所以最终落地成了原创森林小队、原创海底怪物生态，以及一张开放式森林山地地图。

这次最大的收获不是“做了一个游戏”，而是把一个模糊的灵感，压缩成了可运行、可测试、可发布的网页 MVP。

项目定位

游戏的核心循环是：选择角色，进入开放森林地图，移动走位，自动法术攻击，击败怪物，拾取经验，三选一升级，再继续面对更高压的波次。 它不做联机、不做账号系统、不做复杂剧情，而是先把“移动手感 + 法术反馈 + 生存压力”这三件事跑通。

技术栈

TypeScript Three.js Vite Vitest HTML UI LocalStorage Chrome DevTools Protocol

项目一开始使用 Phaser 3 做了 2D MVP。后来因为移动操作和表现力的问题，我把主入口切到了 Three.js， 用 WebGLRenderer 渲染 3D 场景，用自维护的输入状态解决连续移动，用 DOM 层承载菜单、HUD、升级和结算 UI。

核心功能

3D 森林地图 包含山地空地、泥路、河道、木屋、矿洞、树木和岩石障碍。
连续移动控制 键盘使用 WASD / 方向键，移动端使用拖拽摇杆，按住即可持续移动。
角色选择 三名原创森林小队角色，分别偏向稳健、防守、发明爆发和灵活走位。
自动法术战斗 松针法球、溪流连锁、篝火爆鸣、灵木图腾形成不同战斗节奏。
攻击与命中特效 包含法球发射、命中火花、爆炸圆环、连锁光束、拾取闪光。
升级与存档 经验升级后触发三选一强化，本地保存最高分、最长生存时间和音效偏好。

从 2D 到 3D 的重构

2D 版本能验证核心循环，但操作上出现了“不够连续”的问题。这个问题本质上不是单个按键事件没响应， 而是移动状态没有被稳定地作为“持续输入”来管理。

3D 版本里，我没有继续依赖旧的物理移动，而是自己维护一个 Set<string> 存储当前按下的键。 每一帧根据这个集合计算移动方向，再乘以角色速度和 delta time。这样按住键时，角色会稳定地连续移动；松开时，状态会被移除。

战斗系统怎么落地

战斗系统延续了数据驱动的设计：角色、敌人、法术、波次都拆成独立配置。游戏循环只负责读取这些配置，生成实体并更新行为。 这样后续要加新角色、新怪物或新法术，不需要把主循环改得乱七八糟。

敌人生态

敌人不是简单地一窝蜂贴脸，而是分成近战追击、远程泡泡骚扰和精英高血量压场。波次会随时间增加数量、刷新速度和敌人类型， 让玩家在前几分钟能上手，后面逐渐感到压力。

法术反馈

3D 版本最明显的提升是反馈感。法球飞行时有发光球体，命中时有火花和圆环，连锁攻击会在目标之间拉出光束。 这些效果不只是装饰，它们让玩家能快速理解“我打中了什么”“伤害从哪里来”“现在场面是否危险”。

UI 与体验

游戏 UI 没有做成复杂菜单，而是只保留高频入口：开始、角色选择、暂停、升级、结算和本地最高分。 角色选择放在首页，HUD 保持在左上角，暂停按钮在右上角，移动提示在右下角。

这类生存游戏的 UI 不应该抢走注意力。真正要被看见的是地图、怪物、玩家位置和攻击轨迹。 所以我把 UI 做得比较克制，尽量让它像游戏状态面板，而不是一个盖在游戏上的网页。

验证过程

项目不是写完就算。我跑了三类验证：

  • npm test：验证伤害计算、升级抽取、波次增长和本地存档。
  • npm run build：确保 TypeScript 和 Vite 生产构建通过。
  • node tests/browser-smoke.mjs：用本机 Chrome 自动打开页面、选择角色、进入游戏、模拟按住移动，并检查控制台异常。

我还用截图确认了菜单和游戏画面不是空画布，HUD 没有明显重叠，3D 场景和攻击反馈都能看到。

可以继续优化的方向

  • 为每个角色做更明显的专属技能，而不只是数值差异。
  • 增加更多法术联动，例如水 + 木触发藤蔓扩散，火 + 图腾触发范围燃烧。
  • 给敌人加入更清晰的攻击前摇和危险提示。
  • 增加小地图、成就和局外成长，但要避免把 MVP 复杂化。
  • 未来如果要上线展示，可以加 GitHub Pages / Vercel 自动部署流程。

总结

这次项目从想法到 2D MVP，再到 3D 重构，最有价值的是不断把问题具体化： “操作有问题”最后变成了输入状态管理，“想要更有表现力”最后变成了 Three.js 场景和攻击特效， “想要可发布”最后变成了测试、构建、浏览器烟测和 GitHub 仓库。

森林法术旅团现在还只是 MVP，但它已经具备一个小游戏最重要的基础：能玩、能看懂、能扩展，也能被继续打磨。
