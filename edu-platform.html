某教育平台项目

一个面向教育服务企业的全栈网站平台。重点不是“把页面做出来”，而是把品牌展示、内容运营、咨询线索和后台维护，收敛成一套可以持续交付的业务系统。

Next.js 15React 18TypeScriptMySQL + Drizzle

项目背景与目标

原有内容依赖人工修改页面，更新成本高、展示内容难以复用，咨询信息也容易散落在不同渠道。我的目标是把它升级为“前台可转化、后台可运营、数据可维护”的完整平台，让非技术人员也能独立完成日常内容更新。

10+可运营内容模块
2套中英文展示体验
1条咨询线索闭环

核心功能

围绕访客决策路径组织信息，同时为运营人员提供结构化管理能力。

01 / 转化型首页

用数据统计、服务项目、优势、录取数据、案例和资讯建立从认知到咨询的内容节奏。

02 / 内容运营后台

课程、文章、案例、视频、轮播图、办公室与首页配置统一管理，支持排序、发布和推荐。

03 / 咨询线索闭环

前台表单收集姓名、联系方式和咨询方向，后台集中查看，避免线索在聊天工具中丢失。

04 / 国际化与 SEO

公共导航、核心文案和页面元信息支持中英文切换，并补齐 sitemap、robots 和语义化页面结构。

系统架构

采用前后端一体的 Next.js App Router 架构，页面、API、认证和数据访问在同一项目内协作，减少跨服务联调成本。

访客端 → 页面路由 / 中英文切换 / 内容浏览 / 咨询表单
业务 API → 参数校验 / 分页查询 / CRUD / 文件上传 / 健康检查
数据层 → Drizzle ORM → MySQL 8.0
管理端 → NextAuth Credentials → 权限保护 → 内容编辑工作流
App RouterNextAuthDrizzle ORMTailwind CSSREST APIResponsive UI

关键难点与解决方案

  • 内容既要灵活又要稳定：将首页区块和业务资源拆成独立数据表，用排序、启用状态和推荐字段控制展示，避免每次改文案都改代码。
  • 前后台不能各自失控：复用 API 参数解析、分页和资源编辑组件，统一新增、编辑、删除和异常反馈行为，降低维护成本。
  • 上传与生产环境要可落地：补齐上传接口、类型校验和静态访问路由，并按 Node.js、PM2、Nginx 的部署方式组织项目。
  • 页面不只追求“能看”：针对桌面端和移动端调整导航、卡片密度、表单布局和内容层级，让高频浏览和后台编辑都更顺手。

我的贡献与交付结果

负责从需求拆解、数据结构设计、页面实现、后台 CRUD、认证保护到部署文档整理的完整链路。最终交付的是一套可演示、可维护、可继续扩展的业务平台，而不是一次性静态页面。

工程化意识

把重复逻辑沉淀为共享 Hook、API 工具和编辑组件，保持前后台行为一致。

业务理解

围绕用户决策和运营工作流安排信息架构，知道每个字段最终服务于什么动作。
